# ADR-011: Generated Frontend Types from OpenAPI

**Status**: Accepted
**Date**: 2026-08-01
**Deciders**: Engineering

## Context

Hand-maintained TypeScript types that mirror a backend API drift over time.
The MVP wedge frontend must consume the frozen `/api/v1/` contract
(ADR-010) reliably; drift between types and actual responses causes subtle
bugs that are hard to detect.

## Decision

Frontend TypeScript types are **generated from the backend OpenAPI schema**,
never handwritten. The generation tool is `openapi-typescript` (or equivalent).

```
Backend (FastAPI)
    │
    ▼
OpenAPI schema (auto-generated by FastAPI at /openapi.json)
    │
    ▼
openapi-typescript
    │
    ▼
frontend/types/api.ts (committed to repo)
    │
    ▼
Frontend code consumes generated types directly
```

The generation step runs:
- On every backend change (CI) — fails the build if the generated types
  are not regenerated.
- Manually via `npm run codegen` — developer runs this after pulling backend
  changes.

## Consequences

**Positive**:
- Type drift is impossible — types come from the source of truth.
- Refactoring the backend breaks the frontend build immediately, forcing
  aligned updates.
- No manual type maintenance.

**Negative**:
- Generated types can be verbose. Mitigation: a single barrel file
  (`frontend/types/api.ts`) is the only generated file; it is consumed
  uniformly.
- Tooling lock-in: changing generators later requires a one-shot migration.

## Migration Plan

1. Add `npm run codegen` script to `frontend/package.json`.
2. CI step: after backend tests pass, run `npm run codegen` in the frontend
   job; fail if `git status` shows the generated file changed.
3. Frontend code imports from `frontend/types/api.ts` only.
